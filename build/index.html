Layer 1 · Issuer

L1 — Identity

typ: "sd+jwt"
Root SD-JWT. Signed by Issuer. Binds user's public key. ~1 year.
✦ Signature
signer: Issuer
key: Issuer private key · resolved via JWKS (kid in header)
Header (always visible)
alg = "ES256"REQSigning algorithm. ECDSA P-256 + SHA-256.
typ = "sd+jwt"REQSD-JWT token type (RFC 9901). Prevents type confusion.
kid = issuer key idREQIssuer's key id. Resolved via published JWKS.
Payload (always visible)
iss = issuer URIREQIssuer identifier URI. Identifies the financial institution or payment network that signed the L1. MUST be a stable, dereferenceable URI.
sub = user idREQEnd-user subject identifier.
iatREQIssued-at timestamp.
expREQExpiration. SHOULD ≤ 1 year. Clock skew: 300s.
vct = credential type URIREQCredential type profile (e.g. Mastercard card credential).
cnf.jwk = User Pub KeyREQUser's public key (RFC 7800). L2 MUST be signed by matching private key.
pan_last_four = "1234"REQLast 4 PAN digits. Card identification for routing.
scheme = "mastercard"REQPayment scheme identifier.
card_idOPTAdditional card id. Multi-card disambiguation.
_sd_alg = "sha-256"REQHashing algorithm for selective disclosure. MUST be "sha-256".
Selectively Disclosable
emailOPTUser email. Disclosed only for identity verification.
No sd_hash — root credential. The entire serialized L1 is hashed by L2's sd_hash.

L1 cnf.jwk
L2 sd_hash
= B64U(SHA-256(L1))
